# 图片到艺术花艺｜标准案例包

## 用途

本案例包把 CASE-001～CASE-021 的长篇研究拆解压缩为可快速检索的经验卡。它用于帮助 Codex 学习“视觉语言如何被转译为花艺”，不用于照抄历史花束，也不替代主规则文档。

每个案例只保留决定设计判断的内容：视觉核心、信息特征、载体分配、结构、色彩关系、动势、物理气质、可迁移规则与禁止项。

## 目录结构

```text
floral-case-library/
├── README.md
├── case-001/
│   ├── source.jpg
│   ├── bouquet.jpg
│   └── case.yaml
├── ...
└── case-021/
```

若无法确认独立原参考图，则不伪造 `source.jpg`，改放 `source.MISSING.md` 说明缺失情况。当前 CASE-020 使用这种处理。

## 检索规则

1. 先从输入图提取 `semantic_core`、色彩关系、焦点架构、空间、动势与物理材质，再检索案例；不要先按“蓝色、红色”等单一色名匹配。
2. 每次优先读取最接近的 1～3 个案例，不要默认加载全部 21 个案例。
3. 优先匹配机制：`motion.primary`、`structure.focus_architecture`、`palette.mode`、`physical_dna`、`retrieval_tags`。
4. 同题材案例要做反例比较。例如：CASE-001 是透明水感，CASE-006 是深蓝夜色，CASE-014 是冷色梦境；三者不能共用“蓝色模板”。
5. 复用 `key_rule` 和载体分配逻辑，不复用具体花材组合、包装造型或装饰物。
6. 若多个案例都接近，先保留输入图的一级信息，再用案例补足不确定的结构判断，禁止拼贴式混搭。

## 命名规范

- 案例目录：`case-NNN`，三位数字连续编号。
- 原参考图：`source.jpg`。
- 花艺结果图：`bouquet.jpg`。
- 精简卡片：`case.yaml`，UTF-8 编码。
- 缺失说明：`source.MISSING.md` 或 `bouquet.MISSING.md`。
- 新版本若只改卡片，保持案例编号不变；若视觉映射机制发生实质变化，新增案例编号，不覆盖旧案例。

## 图片来源与质量说明

本包使用当前引用对话及其附件中能够定位到的最高质量素材。历史资料大多只保留了“花束主图 + 小尺寸原参考图”的合成图：

- `source.jpg` 是从合成图中的参考图区域裁出的检索用副本，分辨率有限。
- `bouquet.jpg` 保留当前能定位到的最高分辨率历史合成图，因此可能仍含参考图缩略图、卡片或文字。
- 这些图足以支持视觉检索和转译逻辑学习，但不应视为可直接发布的纯净成品图。
- 将来获得独立高清原图或纯净花束图时，可直接按同名文件替换，不需要修改 `case.yaml`。

## `case.yaml` 字段约定

- `case_id`：三位数字字符串。
- `title`：输入类型到花艺类型的简短标题。
- `semantic_core`：一句话视觉核心，不做对象清单。
- `key_features`：必须保留的 3～5 个高权重特征。
- `mapping`：花、枝、叶/草、包装、背板、特殊材料与留白分别承担什么。
- `structure`：轮廓、尺度、密度、重心、焦点架构与不对称程度。
- `palette`：颜色组织方式，而非只列主色。
- `motion`：主/次动势、方向与强度。
- `physical_dna`：硬度、重力感与材质身份。
- `key_rule`：本案例最值得迁移的一条规则。
- `avoid`：最容易把案例做俗或做错的方式。
- `retrieval_tags`：建议用于快速搜索的机制标签。
